How a project starts

A conversation is not a contract. Work begins once we have agreed in writing on scope, price and rough timing, whether that is a signed document or a clear email thread. Anything outside that agreed scope is new work, quoted separately.

Estimates are estimates. We will tell you as soon as we know that something is going to take longer than we said, which on rescue work happens more often than on a build from scratch.

Vibe coding rescue

Rescue work means taking over a codebase somebody else, or some AI tool, already wrote. That carries risks a fresh build does not, so it is worth being blunt about them.

  • We start with an audit. Sometimes the audit says the code cannot reasonably be saved and a rewrite is cheaper. We will tell you that instead of billing you to patch it, and the audit is still chargeable.
  • We cannot promise that every existing feature survives. Some of them were never working in the first place.
  • You need to actually own the project, or have permission from whoever does. We will ask.
  • If the original code infringes somebody's licence or copyright, that is on the project owner, not on us. We will flag anything we notice.
  • We ask for the narrowest access we need, and we expect you to rotate credentials after handover.

Beyond that window, everything is delivered as it is. We do not promise that software will be uninterrupted or free of every error, and we do not control the uptime of the platforms it runs on.
